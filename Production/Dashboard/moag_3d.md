# Моаг: интерактивный просмотр

В галерее `World/ships/moag/` вкладка «3D-модель» ведёт на `World/ships/moag/model/`. Публикуется рабочий внешний объём по концепту moag041, версия v05. Это просмотр предложения, не фиксация принятого дизайна или размеров станции.

Первую загрузку модели запускает кнопка. Доступны вращение, масштаб, общий/верхний/нижний ракурсы, шпиль, кант и полноэкранный режим в поддерживающих его браузерах. До загрузки и без JavaScript остаётся постер. При сетевой ошибке кнопка «Попробовать снова» перезагружает страницу и возобновляет загрузку, сбрасывая также состояние Draco-декодера. Автовращение выключено по умолчанию.

## Файлы и обновление

- `Production/Dashboard/moag_model_viewer.html` — авторский шаблон страницы; `scripts/build_world.py` собирает его и активирует вкладку в галерее.
- `docs/World/ships/moag/model/viewer.js` и `viewer.css` — поведение и оформление.
- `moag041-v05.glb` — 40 724 700 байт, 6 444 233 треугольника, 15 примитивов отрисовки. `manifest.json` хранит контрольные суммы и параметры экспорта.
- `poster-v05.webp` — Cycles-рендер той же v05, уменьшенный до 1600 px.
- `docs/World/vendor/` — закреплённый model-viewer 4.1.0 и локальный Draco-декодер с [лицензиями](../../docs/World/vendor/NOTICE.md); для 3D нет обращения к CDN или загрузки файлов пользователя на внешний сервис.

Исходный Blender-файл v05 хранится отдельно и экспортом не перезаписывается. Его 4K-карты остаются в исходнике; браузерный GLB использует PBR-производные 1024 × 576, повторяющиеся по поверхности. Cycles и браузер используют разное освещение, поэтому изображения не совпадают попиксельно.

Для повторного экспорта v05 использовать отдельный временный каталог:

```sh
blender --background --factory-startup --disable-autoexec --python-exit-code 1 \
  --python scripts/export_moag_web.py -- --source /path/to/moag041_v05.blend --output /path/to/scratch
node scripts/optimize_moag_web.cjs /path/to/scratch/moag041-v05-raw.glb docs/World/ships/moag/model/moag041-v05.glb
python3 scripts/build_world.py
```

Экспорт проверен в Blender 5.2.3 LTS. Оптимизатор требует Node.js, `@gltf-transform/core`, `@gltf-transform/extensions` и `@gltf-transform/functions` 4.5.1, `meshoptimizer` 0.24.0, `draco3dgltf` 1.5.9, `sharp` 0.34.5. Эти зависимости нужны только при пересборке, не сайту.

При замене GLB обновить постер, размер рядом с кнопкой загрузки и `manifest.json`. Для следующей версии использовать новые имена GLB и постера; обновить имя экспорта и метку версии в `scripts/export_moag_web.py`, путь GLB в `viewer.js`, версию и путь постера в шаблоне страницы, затем пересобрать сайт. Новые имена исключают использование старых файлов из браузерного кеша. Проверять не только общий вид, но и швы/окна крупно: упрощение без учёта нормалей или грубое квантование создаёт артефакты на этих деталях.

## Проверка

```sh
python3 scripts/validate.py
python3 scripts/validate_world.py
# В отдельном терминале:
python3 -m http.server 8774 --bind 127.0.0.1 --directory docs
# При установленном Playwright 1.56.1:
BASE_URL=http://127.0.0.1:8774 node scripts/test_moag_model.cjs
```

Браузерный тест проверяет вход из галереи, отложенную загрузку настоящего GLB, мышь/клавиатуру, масштаб, пять ракурсов, автоворот, полноэкранный режим, мобильную ширину, локальный декодер, восстановление после HTTP 503 для GLB и Draco-декодера и постер без JavaScript. `CHROME_BIN` позволяет указать другой Chrome; `SHOT_DIR` — каталог контрольных изображений.

Проверены Chrome на Mac и компоновка 390 × 844. Производительность на реальном телефоне не измерялась; 6,4 млн треугольников могут быть тяжёлыми для слабого GPU. Проверка интерфейса не является творческим принятием станции.
