# Комментарии World через Giscus

Состояние на 26 октября 2026: Discussions включены, репозиторий публичный. Пользователь установил Giscus только для Alive. Категория Comments создана в формате Restricted Announcement и проверена в интерфейсе GitHub. Реальные ID получены через API Giscus; конфигурация включена. Видимость репозитория не менялась.

## Проверка и повторная настройка

Войти в GitHub в браузере владельца. Установить официальное [приложение Giscus](https://github.com/apps/giscus) только для `esannikov/Alive`. В Discussions создать категорию `Comments` формата Announcement. В такой категории новые обсуждения создают сопровождающие и Giscus; это не ограничение «только бот».

После этого выполнить:

```sh
python3 scripts/check_world_comments.py
```

Команда только проверяет состояние и возвращает реальные `repoId` и `categoryId` из официального API Giscus. Не меняет доступ, не устанавливает приложение и не отправляет комментарии. После проверки формата категории в GitHub перенести значения в [comments.json](comments.json), поставить `enabled: true`, пересобрать и проверить World.

## Конфигурация

Проверенные ID: репозиторий `R_kgDOVCLQyQ`, категория Comments `DIC_kwDOVCLQyc4DJpty`. Настройки: pathname, strict=1, реакции, поле ввода сверху, русский язык, тёмная тема (World всегда тёмный). В галереях компактный блок находится внутри viewer сразу после подписи большого изображения, перед служебными ссылками и миниатюрами. На других страницах — в конце main. По умолчанию блок свёрнут, скрипт загружается только при раскрытии, iframe использует loading=lazy. Один тред относится ко всей странице; смена кадра меняет только кнопку копирования кода.

`/index.html` нормализуется к адресу каталога с сохранением параметров и кода изображения. Это предотвращает два обсуждения для одной страницы. Коды изображений и query-параметры не входят в ключ обсуждения. При включённых комментариях sessionStorage хранит только последний код кадра для страницы, чтобы вернуть его после OAuth-перехода Giscus; при отключённом хранилище сама галерея продолжает работать. Справка и галерея имеют разные pathname и поэтому разные треды. Обсуждения первого уровня и вложенных страниц разделены строгим сопоставлением Giscus.

Новый тред появляется при первом комментарии или реакции. Тестовые комментарии не публикуются. При ошибке остаётся ссылка на обсуждения GitHub. Для чтения вход не нужен; для комментирования посетитель авторизует Giscus через GitHub. Комментарии публичны.

## Проверки

```sh
python3 scripts/build_world.py
python3 scripts/validate_world.py
python3 scripts/validate_roadmap.py
python3 scripts/validate.py
node scripts/test_world_comments.cjs
```

Браузерный тест использует локальный имитатор виджета и не отправляет внешних сообщений. Он проверяет все маршруты, строгие параметры, ленивую загрузку, алиас index.html, сохранение кода после OAuth-возврата, отсутствие двойного виджета, мобильный экран и ошибку загрузки. Настоящий iframe проверен локально: русский интерфейс, форма входа и пустой список комментариев загружаются. Публичную версию проверять после выкладки на страницах персонажа, робота, корабля и обзора; тестовые сообщения не отправлять.

## Лента на главной

`World/index.html` показывает пять последних видимых сообщений и ответов из категории Comments, привязанных к страницам World. На главной отдельной формы Giscus нет. Кнопки ведут к `#comments` нужной страницы.

`scripts/build_world.py` формирует список путей `docs/World/comment-pages.json`. `scripts/sync_world_comments.py` читает GitHub GraphQL с полной пагинацией обсуждений и корневых комментариев; для ответов добирает пять последних видимых записей. Сопоставление использует strict SHA1 Giscus. Посторонние и скрытые обсуждения/комментарии не выводятся, тексты сохраняются без HTML. Скрытый родитель исключает свои ответы из ленты.

Workflow `.github/workflows/world-comments.yml` должен находиться также на default-ветке `main`: GitHub запускает discussion events и schedule только оттуда. Он читает код публикационной ветки `codex/alive-roadmap-site` и меняет только `docs/World/recent-comments.json` в этой ветке. Используется встроенный `GITHUB_TOKEN` с `discussions: read` и `contents: write`; в сайт токен не передаётся. Отдельный сервер и сторонний планировщик не нужны.

Обновление запускается при создании/редактировании/удалении комментариев и обсуждений, вручную и с резервной проверкой раз в 15 минут (GitHub может задержать scheduled run). При неизменном содержимом коммит не создаётся. Главная читает JSON через raw.githubusercontent.com: коммиты GITHUB_TOKEN не запускают обычную сборку Pages. Открытая главная проверяет ленту раз в минуту, пока вкладка видима, и при возвращении во вкладку. Ошибка загрузки не маскируется пустым состоянием; есть повтор и ссылка в Discussions.

Проверка без записи обсуждений: `python3 scripts/test_world_feed.py`, `node scripts/test_world_feed.cjs`. Тестовые комментарии в публичный репозиторий не добавляются.
