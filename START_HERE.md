# Підключення до ALIVE

[Головна](README.md) · [Робоче місце](TEAM_DASHBOARD.md) · [Біблія](Bible/README.md) · [Джерела](Sources/README.md) · [Питання](Decisions/Open_Questions.md)

**Основний спосіб: Obsidian + плагін Git.** Агент один раз установлює потрібні програми й налаштовує копію. Далі ви читаєте та пишете в Obsidian, а готову правку відправляєте командою **Commit-and-sync**.

> [!TIP]
> **Почніть із кроків 1–2 нижче.** Повна технічна інструкція призначена вашому агенту; самостійно виконувати всі її команди не потрібно. GitHub Desktop — додатковий клієнт, а не обов’язкова частина основного способу.

## 1. Акаунт і доступ

1. Створіть власний безкоштовний [акаунт GitHub](https://github.com/signup), якщо його ще немає.
2. Надішліть адміністратору проєкту **тільки свій GitHub-логін** — ім’я профілю. Паролі й токени передавати не потрібно.
3. Прийміть запрошення до [esannikov/Alive](https://github.com/esannikov/Alive), коли воно надійде.

Поки репозиторій відкритий, читати матеріали може будь-хто. Для відправлення правок і доступу після повернення приватного режиму потрібне прийняте запрошення. Сам факт, що ви відкрили сторінку або завантажили файли, цього права не дає.

## 2. Передайте завдання агенту

Потрібен агент із доступом до **вашого комп’ютера**: програм, термінала й папок. Звичайний браузерний чат без такого доступу сам нічого не встановить. Якщо локального агента немає, зверніться до адміністратора по допомогу з підключенням.

**Скопіюйте агенту:**

```text
Підключи мене до ALIVE на цьому комп’ютері за повною інструкцією:
https://raw.githubusercontent.com/esannikov/Alive/main/AGENT_SETUP.md

Визнач ОС, перевір установлені програми й установи відсутні:
Obsidian, Git, GitHub CLI, Python і плагін Git від Vinzent.
Використовуй мій GitHub-акаунт. Пароль, 2FA та потрібні особисті
підтвердження я виконаю самостійно.

Збережи мої наявні сховища й незавершені правки. Налаштуй окрему
локальну копію ALIVE, відкрий командний дашборд і панель Git.
Перевір читання, права запису та автоматичне отримання оновлень.

Я хочу самостійно писати в Obsidian й відправляти готове через
Git: Commit-and-sync. Поясни, як перед цим підготувати робочу гілку.
Автокоміти й автопуші не вмикай. Наприкінці покажи, що перевірено
і що ще потребує запрошення або мого підтвердження.
```

[Відкрити повну інструкцію для агента](AGENT_SETUP.md)

> [!NOTE]
> Під час установлення Obsidian може попросити дозволити Git-плагін у сховищі ALIVE. Перевірте назву **Git**, автора **Vinzent** і сховище **ALIVE**, потім підтвердьте його запуск, якщо погоджуєтеся. Саме завантаження файлів плагіна ще не означає, що він увімкнений.

## 3. Перевірте, що підключення завершене

Агент має показати вам:

- **Obsidian із відкритим ALIVE:** працюють [дашборд](TEAM_DASHBOARD.md), [карта біблії](Bible/README.md) та [PDF роману](Sources/ALIVE.pdf).
- **Панель Git:** видно поточну гілку й локальні зміни.
- **Отримання оновлень:** ручний Pull і запуск автоматики перевірені саме в Obsidian.
- **Права:** окремо підтверджено, чи можете ви відправляти правки. Якщо запрошення ще немає, читати вже можна, але відправлення поки не налаштоване.

Не купуйте Obsidian Sync для цієї схеми. Не підключайте цю папку одночасно до iCloud, OneDrive чи іншого синхронізатора. Налаштування вашого Obsidian зберігаються локально й не розсилаються команді.

## 4. Щоденна робота

| Ваше завдання | Що робити |
| :--- | :--- |
| **Читати** | Відкрийте ALIVE у гілці main. Коли сховище відкрите й автоматика не на паузі, плагін отримує оновлення при запуску та кожні 5 хвилин. |
| **Почати писати** | Скажіть агенту: **«Підготуй робочу гілку для моєї правки»**. Він збереже незавершену роботу, поставить автооновлення на паузу й налаштує гілку для відправлення. Потім пишіть самостійно. |
| **Писати руками** | Відкрийте нотатку. Якщо вона в режимі читання — **Ctrl+E / Cmd+E**. Текст зберігається автоматично на вашому комп’ютері. |
| **Відправити готове** | **Ctrl+P / Cmd+P → Git: Commit-and-sync.** Дочекайтеся повідомлення про успішне відправлення. |
| **Передати на перегляд** | Скажіть агенту або відповідальному редактору: **«Правка відправлена, підготуй запит на перегляд»**. |
| **Після приймання** | Попросіть агента повернути вас до чистої main, отримати спільну версію й відновити автооновлення. |

> [!IMPORTANT]
> **Commit-and-sync відправляє всі поточні неігноровані зміни у підготовлену робочу гілку.** Команда сама не створює pull request і не приймає текст до main. Решта команди побачить правку після її приймання відповідальним редактором і наступного отримання оновлень.

Якщо плагін показав помилку, правки можуть залишатися тільки на вашому комп’ютері. Збережіть роботу й передайте повідомлення агенту; самостійно відкидати файли або примусово перезаписувати версії не потрібно.

## Якщо потрібен GitHub Desktop

Це додатковий візуальний Git-клієнт. Його можна [завантажити окремо](https://desktop.github.com/) і встановити на Mac або Windows. Він не замінює сам Obsidian, його плагін або перевірку доступів. Агент може налаштувати його як резервний спосіб роботи за [повною інструкцією](AGENT_SETUP.md).
